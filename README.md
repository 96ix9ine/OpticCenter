# Итоговый проект: AI-ассистент категорийного менеджера для сети салонов оптики (версия 3.0 — с Web-интерфейсом на React)

## Сеть салонов оптики из 26 магазинов
### Хакатон: 4 дня × 2 часа (MVP версия)

---

## 1. Исполнительное резюме

**Проблема:** Сеть из 26 салонов оптики формирует ассортимент вручную. Категорийный менеджер не успевает учитывать локальную специфику каждого салона, из-за чего возникают дефицит ходовых позиций и избыток неликвида. Особенно критично: солнцезащитные очки (сезонность) и дорогие оправы (закуп на основе личных предпочтений).

**Решение:** AI-помощник с **двумя классификаторами** и **Web-интерфейсом на React**:

1. **Мода (стиль)**: Форма × Материал × Цвет → понимаем, что покупают по стилю.
2. **Анатомия (размеры)**: Длина заушника × Ширина линз × Ширина моста → понимаем, какие размеры востребованы в каждом салоне.

**Стек:**
- **Backend:** Python (FastAPI) — обработка данных, классификация, кластеризация, прогноз.
- **Frontend:** React + TypeScript + Tailwind CSS + Recharts — дашборд, рекомендации, тепловая карта.
- **Данные:** Pandas, Prophet, scikit-learn.
- **Интеграция с 1С:** CSV-выгрузка / REST API.

---

## 2. Бизнес-задача и ценность решения

### 2.1. Почему нужны два классификатора?

В оптике покупатель выбирает оправу по двум независимым измерениям:

| Измерение | Что определяет | Пример |
|-----------|----------------|--------|
| **Мода (стиль)** | Внешний вид: форма, материал, цвет | «Квадратная металлическая чёрная» |
| **Анатомия (размер)** | Посадка на лице: длина заушника, ширина линз, ширина моста | «140 мм × 50 мм × 18 мм» |

**Проблема:** Товар может быть модным, но неподходящим по размеру для конкретного салона.

**Решение:** Два классификатора позволяют сегментировать ассортимент и давать точные рекомендации:

- Класс **«Мода»**: `форма_материал_цвет` (например, `квадратная_металл_черный`).
- Класс **«Анатомия»**: `заушник_ширина_линз_мост` (например, `140_50_18`).

Итоговый класс = `Мода + Анатомия`. Например: `квадратная_металл_черный_140_50_18`.
